## Rule implemented

`src/assembler/run/dedup.rs` collapses contigs whose strand-canonical keys
(`min(upper(seq), reverse_complement(upper(seq)))`) are equal, keeping the first
occurrence. It runs in `write_results::write` for both the default read-backed
path and the optional native multi-contig path. Inputs are read-derived contigs
only: no reference, truth, sample name, score, or project metadata is read.
A byte-identical or opposite-strand copy is the same molecule, so keeping one
preserves all read support; distinct sequences, including distinct molecules in
the opposite orientation, are left intact. Ordering is the existing candidate
order, with a deterministic first-occurrence tie-break.

## Precise scope limit (do not overclaim)

The frozen R042 **native Ivanka output** contains four molecules with distinct
canonical keys (`2ae22268`/324, `edf384f9`/306, `136806cd`/306, `055bc14a`/251).
The new rule is therefore **a no-op on that native set** and, by itself, does
**not** change the frozen physical R042 score. The colliding duplicate pair is
between Ivanka's native `324`/`306` rows and MiCall's downstream `denovo`
contigs (`merged_contigs.fasta` `>2`/`>1`), which are byte-identical copies
generated by the frozen downstream stage from the same reads. The frozen
adapter passes reads only (`env={}`, no `--seeds`), so Ivanka has no seed-based
lever over those copies.

Consequently the R042 flip demonstrated here is a **counterfactual at the
combined-representation level**: it proves that duplicate representation is the
causal class and that a duplicate-free representation selects the 324 winner.
A physical R042 >= 161.1 result requires either a reference-blind downstream
deduplication of `project_stitched_counts` (frozen MiCall / P3, out of scope for
this branch) or a read-only change to Ivanka's emitted contig representation
that is not established to be safe here. Nothing in this branch claims that.
