# Experiment: read-spanning evidence at ambiguous contig joins

**Status:** exploratory, not qualified; this branch must not be merged or
used for a production image without both unchanged acceptance gates.

## Hypothesis

A selected contig may contain a terminal overlap consistent with a cycle,
plus one isolated internal join supported by 31-mers but **not** by
101-base windows in original reads. This can create a long, shifted
sequence that is locally well supported yet difficult for downstream MiCall
to align or stitch correctly. The condition is determined entirely from
the contig and original read sequences, with no reference or truth input.

The experimental Rust code recognizes an exact terminal overlap of at least
200 bases and at most one-third of the sequence length. It requires at least
98% of 101-mer positions to have two supporting original-read occurrences,
plus an internal weak run at least 20 positions long and clear of both ends.
It then emits **two alternative openings of the same candidate cycle**,
one in each orientation, at the observed unsupported-span boundary. It
neither asserts two haplotypes nor chooses an opening using a known genome.
Short, unrepeated or low-coverage contigs remain on the original path.

## Outstanding validation

**Two similar full-length contigs might compete for read mappings in MiCall.**
Only an integrated MiCall A/B test, with source-pinned dedicated images,
can establish whether the alternative openings improve final MAX consensus,
coverage, runtime and original-pair attribution. Run representative real
cases, all HXB2 families and the complete original physical-198 comparison
before merging. Preserve the six other assemblers, exact images and strict
all-real-exponent PSI gates. Do not choose, suppress or rank candidates by
reference similarity, even if the benchmark would improve.
